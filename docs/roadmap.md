# Next steps

The initial skill has four workflows and eight topic references. The immediate work is to test its judgment on more systems, not to add more packaging machinery.

## Validate the useful paths

- Repeat the RAG review with and without the skill in fresh sessions. Add a held-out variant so the authoring fixture is not the only test.
- Exercise hardening on a real defect and verify both the security property and the legitimate task.
- Try the design and evaluation workflows on a bounded agent application.
- Add cases for tool argument authorization, approval replay, MCP sessions and token audiences, cumulative budgets, and cancellation before commit.
- Record actual reference loading, missed findings, unsupported findings, and unnecessary approval requests.

## Before a public release

- Test the installer and the installed skill in each advertised host.
- Set up a private reporting channel.
- Recheck version-sensitive source material and attribution.
- Publish cases, model/host configuration, raw results and limitations. Keep private project evidence private.

## Expand when experience supports it

Dedicated multi-agent, model-lifecycle, incident-response and governance workflows need deeper sources and realistic evaluations. Keep those limits explicit until the work is done.

Split the package into independently installable skills only if their use cases and required references differ enough to justify it. The current four tasks share the same security boundaries, so one install avoids duplicated guidance and hidden dependencies.
